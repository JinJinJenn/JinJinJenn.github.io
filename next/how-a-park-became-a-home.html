How a park became a home

6 Nov 2026 · MoveAnywhere

In this story 5 sections
  1. What "half-broken" looked like
  2. Why eleven tries failed
  3. The road here
  4. Changing the lot before it loads
  5. Checking the move survives a reload

I wanted to open Manage Worlds, pick a household and move them into any lot, including a park, just like a normal move. The base game doesn't allow that, and the first versions of the mod forced the move through but left the park half-broken.

What "half-broken" looked like

The household moved in, but the lot still said Park. The lot-type dropdown was locked ("can't be changed while the lot is owned"), the build catalog showed only Park Items with red, unaffordable tiles, and there was a $0 business wallet instead of the family's funds.

Why eleven tries failed

Each earlier version tried to turn the park into a residential lot while the player was standing in it. That change makes the game tear the lot down and rebuild it (you get a white "Building Lot" screen) and it still didn't fix the lot's saved type. Worse, a Manage Worlds move isn't handled by the game's scripts at all; the engine itself writes the move straight into the save data. Our code never even got to run at the right moment.

The road here

  • We started with console commands, then tried overriding the "move" commands, but the Manage Worlds move never went through either.
  • The "not enough funds" and "can't live on a non-residential lot" checks live in the game's Flash interface. Rebuilding those files with the usual tools crashed the game on the loading screen, while editing the same bytes in place didn't.
  • Changing the lot type on the spot brought up the white "Building Lot" screen, or left us with a lot that said Residential to our code while the menus still read Park.
  • Clearing the "venue owner" turned out to be a red herring because it changed nothing visible.
  • Reading the game's own code finally showed us that the engine handles the move itself, and where the lot type is really stored.

Changing the lot before it loads

The engine writes the move into the save data, and then, when the lot loads, reads the lot's type from that same data. So the mod now waits for the moment the save data is released after a move, and any lot a household has just moved into that isn't residential gets its saved type changed to residential. The lot then loads as an ordinary home. We never touch a lot that's currently loaded, which is what caused the rebuild screen.

The fix is only a handful of lines, but finding the right place for them took reading a lot of the game's own code.

Checking the move survives a reload

The automated test follows the move through the real menus, opens build mode, saves, restarts the game and checks the lot again. Version 13.1 passed all 28 checks on 6 November 2026. With the mod switched off, the same test caught the broken park setup.

Follow-up, 6 November 2026: The next round of MoveAnywhere testing covered moving from inside the game and onto an occupied lot, along with low-funds households and existing park-home saves. Those tests passed on copies of a save. The in-game move uses a Sim interaction rather than a phone option in this version of the game.
