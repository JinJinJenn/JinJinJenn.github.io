How a park became a home

6 Nov 2026 · MoveAnywhere

The goal sounds small: open Manage Worlds, pick a household, and move them into any lot, a park included, like a normal move. In the base game you can't. And the first versions of the mod that forced it through left the park half-broken.

What "half-broken" looked like

The household moved in, but the lot still said Park. The lot-type dropdown was locked ("can't be changed while the lot is owned"), the build catalog showed only Park Items with red, unaffordable tiles, and there was a $0 business wallet instead of the family's funds.

Why eleven tries failed

Each earlier version tried to turn the park into a residential lot while the player was standing in it. That change makes the game tear the lot down and rebuild it (you get a white "Building Lot" screen) and it still didn't fix the lot's saved type. Worse, a Manage Worlds move isn't handled by the game's scripts at all; the engine itself writes the move straight into the save data. Our code never even got to run at the right moment.

The road here

  • First tries: console commands, then overriding the "move" commands. The Manage Worlds move never went through them.
  • Patching the menu itself: the "not enough funds" and "can't live on a non-residential lot" checks live in the game's Flash interface. Rebuilding those files with the usual tools crashed the game on the loading screen; editing the same bytes in place didn't.
  • Changing the lot type on the spot: got us the white "Building Lot" screen, or a lot that said Residential to our code while the menus still read Park.
  • Clearing the "venue owner": a red herring. It changed nothing visible.
  • Reading the game's own code instead of guessing: that's what showed the engine does the move itself, and where the lot type is really stored.

The fix: change when, not how

The engine writes the move into the save data, and then, when the lot loads, reads the lot's type from that same data. So the mod now waits for the moment the save data is released after a move, and any lot a household has just moved into that isn't residential gets its saved type changed to residential. The lot then loads as an ordinary home. We never touch a lot that's currently loaded, which is what caused the rebuild screen.

It's a handful of lines. Finding the right place for them took reading a lot of the game's own code.

How we know it works

An automated test moves a household into the park through the real menus, opens build mode, saves, restarts the game and checks again. Last run: version 13.1, 28 of 28 checks passed. The same test with the mod switched off fails, which is the point: a pass has to mean something.

Still to test: moving from the in-game phone instead of Manage Worlds, and moving onto a lot where someone already lives.
